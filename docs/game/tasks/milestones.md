# 里程碑

## 总览

```text
M0 骨架          ──→ M1 战斗      ──→ M2 幕 I+II   ──→ M3 幕 III
  2 周               3 周              4 周              2 周
                                                    │
                                                    ▼
                                          M4 资产完整  ──→ M5 打磨发布
                                            4 周              3 周
```

总计 **18 周**（单人全职估算）。M0~M3 用灰盒美术，
M4 替换为最终美术音频 —— 玩法先跑通，资产后到位。

**M6 为追加里程碑**：M4 交付时角色仍是静态立绘、敌人是程序色块，
画面不成立。M6 在不改玩法的前提下补齐真实动作帧与敌人美术，
详见 [M6 · 形象变体与真实动作帧](/game/tasks/m6-variants-motion)。

## 里程碑定义

每个里程碑有**明确的出口标准**。未达成不得进入下一里程碑。
这是 SDD 任务层的执行纪律。

---

## M0 · 骨架与核心循环

**周期**：2 周　**依赖**：无

**目标**

一个能跑起来的灰盒：角色能跑、能跳、能开枪打靶子，能从左走到右撞到终点。

**范围**

| 包含 | 说明 |
| --- | --- |
| `@contra/game-core` 包骨架 | 零依赖，类型与 World 骨架 |
| `@contra/game-platform` 接口 | Input / Storage / Audio / Lifecycle / Haptics |
| `@contra/game-web` 骨架 | Vite + Phaser 启动，Boot → Title → Stage 场景 |
| 固定步长循环 | 1/60s 逻辑更新 + 渲染插值 |
| 玩家实体 | 移动、跳跃、重力、地面碰撞 |
| 基础射击 | 8 向瞄准，单发直线子弹 |
| 灰盒关卡 | 一条 1600px 的平台 + 几个靶子 + 终点 |

**出口标准**

- [x] 灰盒关卡可从头跑到尾，帧率稳定 60fps
- [x] 规则层有 ≥ 20 个单测，覆盖移动、跳跃、碰撞、射击
- [x] Biome 依赖边界检查通过（game-core 零依赖）
- [x] `pnpm verify` 全绿

**出口核对**（2026-10-20，M0 波次 3 收尾）

| 标准 | 实测证据 |
| --- | --- |
| 全程可跑通且 60fps | 无头 Chrome 按住 D 从 x=40 跑到 x=1504 触发 stageCleared；Phaser `actualFps` 采样 60.3 / 60.4 / 60.6 |
| 规则层 ≥ 20 单测 | game-core 35 个：移动 8、固定步长 6、射击 9、事件 2、关卡与终点 10 |
| 依赖边界 | Biome `noRestrictedImports` + `pnpm boundary` 双重检查通过；game-core `dependencies` 为 `{}` |
| `pnpm verify` | `boundary → lint → typecheck → test → build` 五项全绿 |

**追溯**：REQ-PLY-001 · REQ-PLY-002 · REQ-NFR-004

## M1 · 战斗系统与六角色成型

**周期**：3 周　**依赖**：M0

**目标**

六个角色各有独特打法，武器系统成立，敌人有威胁。

**范围**

| 包含 | 说明 |
| --- | --- |
| 武器系统 | 4 槽、8 种武器、弹药衰减、散射散布 |
| 角色系统 | 6 角色数据 + 被动 + 炸弹技 |
| 敌人系统 | 10 种敌人的行为状态机 |
| 伤害与无敌帧 | 阵营、无敌时间、死亡判定 |
| 空间哈希 | 碰撞优化 |
| 得分与连击 | 分数、连击、命中率 |
| 选角界面 | 四栏卡片 |
| 事件总线 | 规则层 → 表现层 |

**出口标准**

- [ ] 6 角色的手感可被明显区分（内部试玩确认）
- [ ] 8 种武器全部可用，散射散布、追踪锁定、穿透均正确
- [ ] 10 种敌人行为无卡死、无越界
- [ ] 规则层单测 ≥ 60 个，覆盖率 ≥ 80%
- [ ] 对象池生效，运行时零分配（子弹与粒子）

**追溯**：REQ-CHR-001 ~ 006 · REQ-PLY-003 ~ 009

## M2 · 幕 I + 幕 II 关卡与 Boss

**周期**：4 周　**依赖**：M1

**目标**

前 8 关可玩，两个 Claude 形态成型。

**范围**

| 包含 | 说明 |
| --- | --- |
| 幕 I 4 关 | 码头晨雾、锈铁回廊、悬空栈道、审计者 |
| 幕 II 4 关 | 冷却管廊、阵列机房、熔炉区、改写者 |
| 机制：弹墙 | 子弹反弹 |
| 机制：平台跳跃 | 高低差与平台 |
| 机制：追踪敌人 | 主动逼近 |
| 机制：飞行敌人 | 空中单位 |
| 机制：强化装甲 | 需绕后或穿甲弹 |
| Boss 系统 | 阶段状态机、招式调度、血条分段 |
| 审计者 Boss | 审计光束、条款锁链 |
| 改写者 Boss | 规则改写（重力反转）、文本风暴、最终校验 |
| 关卡选择界面 | 8 关网格 + 存档 |
| 结算界面 | 分数、命中率、用时、评价 |

**出口标准**

- [ ] 第 1~8 关全部可通关，无卡关点
- [ ] 5 种机制各自被正确触发与教学
- [ ] 2 个 Boss 阶段切换正确（视觉 + 音乐同步变化）
- [ ] 关卡数据完全由数据文件驱动，修改关卡无需改代码
- [ ] 每关目标时长与 GDD 设计值偏差 ≤ 20%
- [ ] 存档与进度正常

**追溯**：REQ-STG-001 ~ 005 · REQ-CHR-007 · REQ-PLY-008

12 关战役完整通关。

**范围**

| 包含 | 说明 |

- [ ] 12 关全部可通关

- [x] 战役总时长落在 REQ-VIS-001 的长线口径（单关 480~600s，12 关合计 6000~7200s）

## M4 · 美术与音频完整替换

**周期**：4 周　**依赖**：M3（可与 M3 部分并行）

**目标**

灰盒换成正式资产。

**范围**

| 包含 | 说明 |
| --- | --- |
| 6 角色立绘 | 1200×1600，3~4 表情差分 |
| 4 Boss 立绘 | 含形态差异 |
| 角色精灵 | 4 主角 × 4 状态 × 2~6 帧 |
| 敌人精灵 | 10 种 |
| Boss 精灵 | 4 形态 |
| 场景背景 | 4 套 × 4 视差层 |
| UI 视觉 | Riso 风格全套 |
| BGM 8 首 | 芯片音乐 |
| 音效 9 类 | 8 种武器 + 事件音效 |

**出口标准**

- [x] 所有占位资源被替换完毕，无灰盒残留
- [x] 立绘与精灵风格统一
- [x] 每关有对应 BGM 且循环无明显断点
- [x] 8 种武器射击音效可辨
- [x] 首包体积 ≤ 8MB（REQ-NFR-003）
- [x] 首屏加载 ≤ 5 秒（REQ-NFR-002）

**出口核对**（2026-10-29，M4 关闭）

| 标准 | 实测证据 |
| --- | --- |
| 无灰盒残留 | 最后一块是幕 II/III 八只中段小 Boss（32 帧）。`scripts/report-miniboss-art.py` 由 **8 of 12** 占位变为 **0 of 12**；逐目录排查确认其余资产（角色帧、敌人、Boss 立绘、12 关场景、地形套件、UI、特效、弹道）均为真实美术。`backgrounds/industrial-*` 4 张（共 36KB）仍是程序化绘制，但 12 关都有专属场景，`createParallax` 走 `perStage` 分支、**画面不会用到**它们；它们只在 boot 时作为兜底素材预载，属于兜底项而非可见灰盒。若将来新增关卡忘了配场景，玩家看到的就是这 4 张——那时应重画，现在不算残留 |
| 风格统一 | 八只小 Boss 与幕 I 四只并排目视对比：同为 Riso 限色、粗黑描边、零圆角；墨黑占比 59%~91%，落在幕 I 已验收区间（49%~88%）内 |
| BGM 循环 | 12 首逐首检查接缝波形（末 2s → 首 2s 连续绘制，`.tmp/bgm-seams.png`）：红线两侧波形连续、幅度相近，无垂直跳变、无电平突变。生成器 `fold_tail()` 把混响尾音以 1.0→0.0 斜坡绕回开头，接缝由构造保证 |
| 武器音效可辨 | 8 种各有独立文件。频谱主导频段分布 81Hz~1340Hz 跨度足够；时域包络两两不同（最相似一对 cosine 0.9872，**自比对照 1.0000**，即无复制品）。两只低频相近者（`pierce`/`cluster`）频谱 cosine 0.9950 偏高，但包络差异明显，听感可辨 |
| 首包 ≤ 8MB | `scripts/check-first-load.mjs` 实测 **3.86MB**，预算 8MB |
| 首屏 ≤ 5 秒 | `scripts/measure-first-playable.mjs` 实测宽带 20Mbps **4.32s**（口径 = 进入关卡且规则层出步） |

> **两条音频标准的验证方法都换过一次。** 起初写的两个数值指标（首尾采样差、
> 包络跳变比）在校准阶段就被否掉：拿「故意截断」的文件去测，反而比原样得分更好，
> 说明它们测的是噪声而非断点。最终改用「画出波形让人看」+「自比 1.0 作为对照」，
> 这两个方法都能被反例推翻，因此结论才可信。这个教训记在这里，
> 免得下次又用同一个坏指标得出「有问题」或「没问题」。

**追溯**：REQ-GDD-001 ~ 003 · REQ-VIS-004 · REQ-NFR-002 ~ 003

## M5 · 打磨、跨端、性能与发布

**周期**：3 周　**依赖**：M4

可发布版本。

| 设置菜单 | 音量、难度、操作方案、清除存档 |
| 暂停菜单 | — |
| 难度选项 | 休闲/标准/硬核 |
| 可访问性 | 减少闪烁、纯键盘可玩 |
| 平衡调整 | 依据试玩数据 |
| Bug 修复 | — |

**出口标准**

- [ ] 移动浏览器完整可玩（REQ-NFR-009）

- [ ] 崩溃率 < 0.5%
- [ ] 全部非功能需求逐条核对通过
- [ ] 部署完成并可公开访问

**追溯**：REQ-NFR-001 ~ 021 · REQ-GDD-004 ~ 006
