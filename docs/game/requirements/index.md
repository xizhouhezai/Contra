# 需求层索引

需求层定义**做什么**，不定义**怎么做**。
任何在需求层出现的实现词汇（类名、框架、文件路径）都说明这条需求写错了地方。

## 需求条目格式

每条需求有唯一编号，格式 `<前缀>-<三位序号>`，例如 `REQ-PLY-007`。

| 字段 | 说明 |
| --- | --- |
| **编号** | 稳定标识。一旦发布不复用、不重排 |
| **标题** | 一句话说明这条要求什么 |
| **优先级** | `P0` 必须有 / `P1` 应该有 / `P2` 可以有 |
| **验收** | 可观测、可判定的达成条件 |
| **追溯** | 实现它的设计条目与任务编号 |

## 变更规则

1. 需求变更 → 先改需求文档并更新编号 → 再改受影响的设计 → 最后改任务
2. 编号一旦发布**不复用、不重排**。作废的需求标注「已作废」并说明替代编号
3. 设计或任务若无法回指需求编号，说明它没有需求支撑 —— 应删除或补需求
4. 需求条目被设计条目覆盖时，设计条目标注「实现：REQ-xxx」
