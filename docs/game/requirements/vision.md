# 愿景与设计支柱

## 一句话

**Contra 是一款跑轰式横版动作游戏 —— 六个大模型拟人化的「宠物娘」并肩作战，突袭由 Claude 与 GPT 镇守的十二道封锁线。**

## 产品定位

| 维度 | 定义 |
| --- | --- |
| 类型 | 横版跑轰（Run and Gun） |
| 视角 | 2D 侧视，卷轴式 |
| 单局时长 | 25~40 分钟（12 关战役） |
| 联机 | 单人为主，双人合作机制预留，首发不启用 |
| 平台 | Web 优先（桌面 + 移动浏览器），后续扩展原生 App |
| 技术栈 | Phaser 3 + TypeScript |
| 受众 | 熟悉魂斗罗的玩家、模型社区用户、需要短时高强度体验的休闲玩家 |

## 目标玩家

**核心受众 · 模型社区开发者**
他们认识 DeepSeek、Qwen、豆包、GLM、Claude、GPT 这些名字。角色不是皮肤，
而是**性格的具象化** —— 他们的战斗方式应该能让人一眼猜出「这是谁」。

**次要受众 · 魂斗罗血脉玩家**
熟悉横版跑轰的操作节奏与关卡结构，需要的是「熟悉的爽感 + 新的内容」。

**长尾受众 · 碎片时间玩家**
单关 3~5 分钟，随时中断随时回来，30 分钟内能完成一轮战役。

## 核心体验支柱

### 支柱一 · 手感优先

横版跑轰的乐趣来自**连续的移动与射击**，而非解谜或数值养成。
任何设计决策若损害操作的即时反馈，优先级让位。

- 移动必须跟手，跳跃弧线可预期
- 射击反馈即时，命中要有明确视觉与音效
- 死亡到重试 ≤ 3 秒，惩罚是重打而非等待

### 支柱二 · 角色即性格

六个角色必须在**第一眼**就被区分开，**第一次使用**就能感到不同。
差异落在三个维度，且三者叠加：

| 维度 | 表现 |
| --- | --- |
| 初始武器 | 决定远程输出的形态：散射 / 连射 / 追踪 / 均衡 |
| 被动技能 | 决定生存与机动倾向：机动、续航、爆发、支援 |
| 炸弹技 | 决定关键时刻的翻盘手段 |

> **反模式**：把角色做成「数值不同的同一个模板」。六个角色应当玩起来像六款不同的游戏。

### 支柱三 · 关卡即舞台

12 关划分三幕，每幕有自己的场景主题、配色、配乐与新机制。
玩家推进战役时应当**看得见世界的变化**，而不只是数字变大。

### 支柱四 · 文档即契约

SDD 规格是唯一事实源。设计变更先改规格，改代码是最后一步。

## 设计原则

1. **可读性优先于真实感**
   子弹慢、伤害大、爆炸明显。玩家在任何时刻都能看清屏幕发生了什么 —— 这也是横版动作游戏能操作高速战斗的前提。

2. **难度来自密度，不来自欺诈**
   敌人多、弹幕密、节奏快都可以；**看不见的伤害源、瞬移攻击、背后偷袭不可以**。

3. **不惩罚熟练，只奖励熟练**
   连击、高分、隐藏收集物给高手更多表达空间，但不设置必须靠反应速度才能过的「像素级」判定。

4. **每个 Boss 都是一场考试**
   Boss 战必须引入该关新学到的一个机制，而非单纯堆血。

5. **移动端不是残血版**
   触屏操作与键盘操作**同等完整**，不是把手机版当附赠品。

6. **规格先于实现**
   任何代码变更若找不到对应的需求编号，说明它不该存在。

## 非目标（明确不做）

| 不做 | 理由 |
| --- | --- |
| 开放世界 / 自由探索 | 与跑轰式关卡结构相悖 |
| 养成 / 装备 / 数值成长 | 与「街机式爽感」冲突，稀释操作乐趣 |
| 多人联网对战 | 首版无服务器，Web 端做实时联机成本过高 |
| 剧情分支与对话系统 | 预算与工期不允许，且不是核心体验 |
| 内购 / 广告 | 保持作品完整性与隐私友好（REQ-NFR-006） |
| 原生 App 首发 | Web 优先验证玩法，App 随后 |

## 成功指标

| 指标 | 目标 | 测量方式 |
| --- | --- | --- |
| 首通完成率 | ≥ 60% 的测试者在 3 次尝试内通关第 1 幕 | 关卡埋点 |
| 单次会话时长 | 中位数 ≥ 18 分钟 | 会话统计 |
| 角色使用分布 | 无单一角色占比 > 40% | 选角统计 |
| 首屏加载 | ≤ 5 秒 | 性能面板 |
| 崩溃率 | < 0.5% | 错误上报 |
