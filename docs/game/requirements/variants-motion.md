# 角色形象变体与动作需求

> 来源：用户需求「除了可以选取不同人物，还希望每个人物可以选取不同形象，
> 比如除了现在的形象，还可以选择 Q 萌版的形象」+「目前的人物是纯贴图图片，
> 希望可以有骨骼运动，比如拿枪动作不同」
> 日期：2026-10-21 ｜ 关联调研：[形象与骨骼调研](/game/design/animation-research)

## 1. 范围

本需求分三层，按依赖顺序推进：

| 层 | 内容 | 交付物 |
| --- | --- | --- |
| **L1 形象变体** | 同一角色可选多套形象（立绘 / Q 萌） | 选角界面二级选择 |
| **L2 程序化动效** | 现有贴图动起来（呼吸 / 后坐 / 受伤） | 无新素材的动态表现 |
| **L3 持枪动作** | 自由瞄准 + 持枪姿态 | 规则层瞄准模型变更 |

## 2. 需求条目

### REQ-VAR-001 形象变体可选

每个角色提供**至少两套**可选形象：一套立绘、一套 Q 萌版。

- **验收**：选角界面可选中角色后继续选择该角色的形象；
- **验收**：选择结果随关卡进入游戏，游戏中显示所选形象；
- **验收**：某角色缺少某形象时该形象不出现，**不报错**。

### REQ-VAR-002 形象持久化

玩家的形象选择在下次启动时保留。

- **验收**：选择后重启浏览器，形象不变；
- **验收**：与角色选择一同保存，两者独立（换角色不丢形象，换形象不丢角色）。

### REQ-VAR-003 比例自适应

Q 萌版素材**尺寸不一致**（实测 202×360、360×202、360×360 混存），
显示时按源图比例缩放，不得拉伸变形。

- **验收**：每套形象按其自身宽高比等比缩放；
- **验收**：横版素材与竖版素材在同一张卡片内不溢出。

### REQ-MOT-001 程序化动效

角色不再是一张静止贴图。**不引入骨骼系统、不需要新素材**。

| 状态 | 表现 |
| --- | --- |
| 待机 | 呼吸：Y 轴 ±1% 缓慢正弦 |
| 开火 | 后坐：短促位移 + 微旋转，随开火事件触发 |
| 受伤 | 朱红闪烁 + 水平抖动 |
| 移动 | 轻微倾斜（朝向移动方向） |

- **验收**：动效在 ActorView 内实现，**不破坏**表现层单向契约（规则层不感知动画）；
- **验收**：开火动效由 shot 事件驱动，不是定时器；
- **验收**：60fps 下动效不产生可测量的帧率下降。

### REQ-MOT-002 动作与玩法状态对应

动效必须反映**真实玩法状态**，不能只是循环播放。

- **验收**：静止时播放呼吸，移动时不播放呼吸；
- **验收**：受伤闪烁只持续受伤后的短暂时间，随后恢复。

### REQ-GUN-001 持枪动作

角色持枪射击，不同武器有不同持枪姿态。

> **前置**：现有素材无法支撑。此项需要新的分件美术，见第 4 节。

- **验收**：角色可见地持有武器；
- **验收**：不同武器类型（直射 / 投掷 / 光束）持枪姿态不同；
- **验收**：开火时武器与手臂协同动作。

### REQ-GUN-002 自由瞄准

持枪姿态要求瞄准角度连续可变，**当前规则层是固定八方向**
（game-core/src/systems/Weapons.ts 的 AIM_DIRECTIONS）。

本项要求规则层支持自由角度瞄准，同时**保持八方向射击可玩**
（现有 12 关与 10 把武器的平衡建立在八方向之上）。

- **验收**：瞄准角度由输入连续推导，不再离散到八向；
- **验收**：八方向作为特例仍然成立（斜 45 度仍命中同方向）；
- **验收**：规则层不依赖具体角度值，全部行为由角度驱动。

## 3. 非功能约束

| 项 | 要求 |
| --- | --- |
| 依赖 | L1/L2 **不引入任何新运行时依赖** |
| 体积 | 新增素材不得使首包超过 8MB（REQ-NFR-003） |
| 性能 | 动效不得使帧率低于 60fps 的 95% |
| 边界 | 规则层仍零依赖，不感知动画与形象 |
| 授权 | 沿用非商业前提；署名表按「角色 → 形象 → 作者」列 |

## 4. L3 持枪动作的前置条件

REQ-GUN-001 **不能只靠代码实现**。调研结论（见调研文档第 4 节）：

1. 现有 portraits/*.webp 是单张完整立绘，**没有可分离的部件**；
2. sprites/*.webp 曾是程序生成的 48px 占位（现已被动作帧替换，见 M6）；
3. 骨骼动画需要**已切分的部件**，Spine 工作流是「建骨骼 → 切图 → 对位 → K 帧」。

因此 L3 需要先产出**分件美术**：

| 交付物 | 数量 | 说明 |
| --- | --- | --- |
| 角色分件 | 6 角色 × 头/躯干/上臂/前臂/腿 × 2 套形象 | 带透明通道 |
| 武器模型 | 10 把武器的可持握形态 | 挂在手部插槽 |
| 动作 | 每套 6 个：待机 / 跑 / 跳 / 受伤 / 开火 / 换弹 | Spine 或等价格式 |

**这是美术产线的升级，不是渲染变更。** 建议作为独立里程碑立项，
并在开工前回答：

- 美术由谁产出（AI 生成 + 人工修，还是外包）；
- 是否采用 Spine（授权 99 美元起）或其他方案；
- 现有立绘是否保留为「立绘形象」与新素材并存。

在分件素材到位前，L3 的可交付部分是 **REQ-GUN-002 自由瞄准** ——
它独立于美术，且能让瞄准手感更精确。

## 5. 验收总则

三层各自可独立验收：

- **L1**：选角界面能选形象，游戏里显示所选形象，重启后保留；
- **L2**：角色在待机/移动/开火/受伤时表现不同，且由真实事件驱动；
- **L3**：瞄准角度连续可变，且八方向行为不变。

**视觉验收用 Midscene**：它能回答「画面上有没有立绘」「动效是否可见」，
这是单元测试做不到的（见 scripts/visual-check.mjs）。
