# 形象变体与骨骼动画调研

> 需求来源：用户提出「每个人物可选取不同形象（如 Q 萌版）」与「希望有骨骼运动，拿枪动作不同」
> 调研日期：2026-10-21 ｜ 结论已落地为 [形象变体与动作需求](/game/requirements/variants-motion)

## 1. 素材现状（已核实）

| 类别 | 数量 | 规格 | 用途 |
| --- | --- | --- | --- |
| 立绘 portraits | 6 张 | 506×900、202×360、160×160 | 已接入选角界面 |
| 梗图 official/meme-* | **57 张** | 202×360 ~ 360×360 | Q 萌版形象库 |
| ZipZipPipe 立绘 | 20 张 | 全身立绘 | 备选形象 |
| 生成精灵表 sprites | 34 张 | 48px 帧 | 占位，非真实美术 |

**57 张梗图是关键发现**：按角色分目录（meme-deepseek 20 张、meme-qwen 6 张……），
本身就是现成的 Q 萌版形象库，不需要下载任何新素材。

> 尺寸实测：梗图**并非全是方形**，多数是 202×360 或 360×202，少数 360×360。
> 另外它们是 **VP8 格式，没有 alpha 通道**，因此带不透明背景，无法抠图。

## 2. 多形象：已实施

每个角色两个维度：形象（立绘 / Q 萌）、表情（常态 / 受伤）。
选角界面按 Q 在所选角色的形象间循环，形象条显示当前进度。

### 体积约束

57 张梗图全量预加载会让产物涨到 8.41MB，超过 8MB 预算。
改为 import.meta.glob 非 eager 模式后：

| 项 | 体积 |
| --- | --- |
| 首包（启动必需） | **1.55MB** |
| 按需加载（音乐 + 梗图） | 6.86MB |

首包远低于预算，梗图在玩家按 Q 时才下载。校验脚本：scripts/check-first-load.mjs。

## 3. 骨骼动画：四条路线

### 3.1 Spine（商业标准）

| 项 | 值 |
| --- | --- |
| 运行时 | @esotericsoftware/spine-phaser-v3 |
| 版本要求 | Phaser ≥ 3.60（本项目 3.90 满足） |
| 授权 | Essential 99 美元 / Professional 449 美元 / Enterprise 50 万美元起 |
| 产物 | .skel + .atlas + .png |

Spine 的 **Skin 机制**天然支持「多套形象 + 不同动作」：换形象是换 skin，换动作是换 animation。

### 3.2 Rive

面向交互式矢量动画，Web 运行时免费。但它是**矢量路径动画**，
导入位图需要先描摹成矢量，对已有 506×900 位图立绘是逆向工作。

### 3.3 AI 自动绑定

UniRig（SIGGRAPH 2025）证明单图自动提取骨骼可行，但输出 **3D 骨架**，
且结果需人工修整。对本项目等于「AI 出初稿 + 人工逐帧修」。

### 3.4 剪纸动画

切成头/身/手臂/腿几块用代码变换。不需要专用编辑器，但**需要人工切图**，
从完整立绘分离干净部件的边缘处理比画骨骼更耗时。

## 4. 为什么骨骼动画在本项目不成立

**不取决于技术难度，而取决于素材。**

1. portraits 是**单张完整立绘**（506×900 整幅插画），没有分层信息；
2. sprites 是**程序生成的 48px 色块**，不是真实美术；
3. 骨骼动画需要**已切分的部件**，Spine 工作流是「建骨骼 → 切图 → 对位 → K 帧」。

用 Spine 意味着 6 角色 × 2 套形象 = **12 次完整的拆件与绑定**，
按单套 2~4 小时估算，是 **24~48 小时的人工美术工时**，且切图边缘会露白。

### 与「拿枪动作」需求的错配

需求说「拿枪动作不同」。但当前游戏是**八方向射击**，
玩家手里**没有枪械模型**，武器是抽象光弹
（game-core/src/data/weapons.ts 里十把武器全是 projectile / throwable / beam）。

做持枪动作实际需要：10 把武器 × 12 套形象 = **120 个武器部件**，
外加每角色 6 个动作。这是**美术产线的升级**，不是渲染方式的改变。

## 5. 中间路线：程序化动效（已实施）

不需要任何新素材，代码量约 60 行：

| 状态 | 表现 |
| --- | --- |
| 待机 | 呼吸：Y 轴 ±1% 缓慢正弦 |
| 开火 | 后坐：短促位移 + 微旋转，由 shot 事件触发 |
| 受伤 | 朱红闪烁 + 水平抖动 |
| 移动 | 轻微倾斜 |

不破坏 ActorView 的单向同步契约（规则层不感知动画）。

## 6. 结论与后续

| 路线 | 结论 |
| --- | --- |
| 多形象 | 已实施，素材已够，无新依赖 |
| 程序化动效 | 已实施，60 行，当天见效 |
| 持枪动作 | 需先产出分件美术，作为独立里程碑 |
| Spine 集成 | 等待分件素材；技术接口已验证可行 |

**若要做持枪动作，需先回答**：

1. 美术由谁产出（AI 生成 + 人工修，还是外包）；
2. Spine 授权买哪一档（99 / 449 美元）；
3. 现有立绘是否保留为「立绘形象」；
4. 战斗形态是否改变 —— 横版动作会改变规则层的移动、瞄准、碰撞模型。
